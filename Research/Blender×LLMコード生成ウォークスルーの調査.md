## TL;DR

- Anthropic の Alex Albert が 2026-09-01 に投稿: **土地の写真1枚を Fable 5.1 に渡す → 家を設計 → Blender(headless)でレンダー → 35秒のシネマティックなウォークスルー動画**を「コードで」生成 ✅。返信で「using blender headless btw」と補足 ✅。再生96万・いいね7,352(9/3時点) ✅
- 既存調査の4系統(BIM/AIパース/平面図→3D/画像→動画AI)に対する **第5系統「LLMがBlenderコードを書いて本物の3Dシーンを作る」**。画像→動画AI(系統4)と違い、**寸法が図面どおり・カメラ自由・尺無制限・1秒あたりの従量課金ゼロ**が利点。弱点は写実性の担保とレンダー時間
- ランドスタイル向けには「土地写真→AIが勝手に設計」ではなく **「実行図PDF→忠実な3D→外観/内観パース+ウォークスルー+日照シミュレーション」を1本のパイプラインで出す**用途が本命。図面に外壁の製品名・色番まで書いてあるので、公正競争規約(完成予想図の明示・現況との乖離禁止)に対応しやすい
- 「土地写真→提案プラン」の元ネタどおりの使い方は、建売の広告ではなく **土地仲介・注文住宅のリード獲得(「この土地にこんな家が建ちます」)** に向く。ただし建築確認前の建売広告は宅建業法33条で不可 ✅
- 次の一手: 浜崎2号棟の実行図PDFで **PoC(外観2枚+内観1枚+15秒ウォークスルー)** を Claude Code + Blender headless で作り、既存の施策1(無償デモ)の中身にする

## 1. 投稿の内容と仕組みの推定

### 事実 ✅
- 本文: "For this one I gave it a picture of a property lot. It designed a house for the lot, rendered it, and produced a cinematic walkthrough."
- 動画: 1280×720・35.4秒(fxtwitter API のメタデータ)。サムネイルは木製階段の踊り場から木枠ガラス戸越しにLDKを見下ろす内観。フローリング・ガラス反射・自然光の表現は写実寄りで、ポリゴン感のない Cycles 系のルック(サムネイル1枚からの判断 ⚠️。X のログイン壁で動画本体は再生確認できず ❓)
- 補足返信: "using blender headless btw"(= GUI を開かず `blender -b` でスクリプト実行)
- 返信で Ryan Smith(@Rye1One)が「Opus 5 で同様のウォークスルーを作った」と16秒動画を投稿 ✅(内容未確認 ❓)。GitHub 等での再現コードの公開は見つからず ❓

### 推定される手順 ⚠️
1. 土地写真を Claude が読み、敷地形状・周辺・方位を推定して住宅のボリューム/間取りを決める
2. Claude が `bpy`(Blender Python API)スクリプトを書く: 壁・床・屋根・開口をメッシュで生成、ガラス/木/フローリングのPBRマテリアル、HDRI or サンライト、カメラのキーフレーム(パス)を設定
3. `blender -b -P build.py` でシーン生成→ `-E CYCLES -a` で連番レンダー(headless)
4. `ffmpeg` で連番を mp4 に結合(必要なら BGM・フェード)
5. 出力を Claude が見て(画像入力)手直し→再レンダー、を数周

この流れ自体は Blender MCP や claude-blender 系の既存事例と同じ一般パターンで、特殊な非公開技術は使っていないと見てよい ⚠️。

## 2. 既存4系統との比較(第5系統としての位置づけ)

| 観点 | 系統1 BIM→D5/Twinmotion | 系統4 画像→動画AI(Runway等) | **系統5 LLM→Blenderコード** |
|---|---|---|---|
| 寸法・建築的整合性 | ◎(3Dモデル前提) | △(1枚絵から動くので破綻する) | **◎(図面座標からメッシュ生成)** |
| カメラ・尺 | ◎ | △(5〜20秒・カメラ指定が粗い) | **◎(任意パス・任意尺)** |
| 写実性 | ◎ | ○(絵としては強い) | ○〜◎(アセット・ライティング次第) |
| 変更対応(仕様変更・別内装) | ○(人が操作) | ×(作り直し) | **◎(パラメータ変えて再レンダー)** |
| 自動化・headless | △(GUIツール) | ◎(API) | **◎(CLIで完結)** |
| 1本あたり変動費 | 人件費 | 10秒 $0.4〜6 | **LLMトークン+レンダー時間(電気代 or クラウドGPU)** |
| 習得・構築コスト | 中(ツール習熟) | 小 | **中〜大(bpy・マテリアル・ライティングの型を作るまで)** |
| ソフト費 | 無料〜17万円/年 | 従量 | **Blender無料(GPL)・生成物の権利は制作者** |

含意:
- 系統4の弱点(寸法破綻・尺の短さ・1物件複カット時のコスト)を系統5が埋める。逆に「雰囲気の良い1枚絵をとにかく早く」なら系統2+4のほうが速い
- **最適解は系統5で正確な3D・カメラパスを作り、必要なら系統2(SD+ControlNet)や画像→動画AIで仕上げのルックを足す**ハイブリッド ⚠️

## 3. 技術面の要点

### ツール ✅
- **Blender MCP**(ahujasid/blender-mcp): 16.3k star・MIT。Claude Code/Claude Desktop/Cursor 等から Blender を双方向操作(シーン操作・マテリアル・任意コード実行)。Poly Haven のアセット取り込みも統合 → 対話的に作る段階に向く。GUI 前提なので「完全自動」には `blender -b` の直叩きが必要
- **Poly Haven**: HDRI・テクスチャ・モデルが CC0(商用可)。BlenderKit アドオン経由で Blender に直接取り込める。**空・外構・床材・家具の写実性はここで稼ぐ**
- **Sun Position**(Blender 標準アドオン): 緯度経度・日時から太陽位置を NOAA 式で再現 → 新座市の座標と日付を入れれば **季節・時刻ごとの日照パース**が同じシーンから出せる(施策5と統合可能)
- Buildify(geometry nodes の建物生成)・Archipack: 壁・窓・階段のパラメトリック生成。日本の住宅向け建材・サッシ・設備(キッチン/UB)の Blender アセットの定番入手先は未確認 ❓ → 各メーカーの 3D データ(LIXIL・TOTO・ニチハ等の BIM/CAD データ)を Blender に読み込めるか要検証

### headless レンダーの制約 ✅⚠️
- macOS では **Eevee は headless(`-b`)非対応**(Linux のみ)。Mac で無人レンダーするなら **Cycles 一択**
- Cycles は Apple Silicon の Metal GPU に対応(3.x以降)。1280×720・デノイズありで 1フレーム数秒〜数十秒が目安 ⚠️ → 24fps×35秒=840フレームで **数時間/本**の見込み。急ぐなら RunPod 等のクラウドGPU(RTX 4090 で1時間 $0.5前後 ⚠️)にレンダーだけ投げる
- 写実性を上げるほどレンダー時間が伸びるので、**SNS リール用は 720p・24fps・サンプル数低め+デノイズ**で割り切り、SUUMO 用静止画だけ高サンプルにする設計が現実的

### 品質で詰まりやすい点 ⚠️
- LLM が書く bpy は「箱を並べる」ところまでは得意だが、**軒・破風・サッシ枠・巾木・幅木・照明器具**などディテールを省くと一気に安っぽくなる → ディテールはアセット(BlenderKit/Poly Haven/メーカーデータ)で補い、LLM には配置とパラメータだけ書かせる
- 図面の読み取り(PDF→座標)は LLM の画像理解に頼ると寸法ずれが出る。**ベクター CAD PDF から線分を抽出**(pdfplumber/ezdxf 経由)して座標を渡すほうが堅い

## 4. ランドスタイル(建売分譲)への適用シナリオ

### A. 本命: 実行図 → 忠実な3D → ビジュアル一式(施策1・2・3・4・5を1パイプラインで)
- 入力: 浜崎3丁目2号棟の実行図PDF(平面詳細1/50・立面4面・仕上げ表・配置図)。**外壁の製品名・色番(ニチハ モエンサイディング M14 グレー×ホワイト×ヴィンテージウッドブラウン)まで書いてある**ので、マテリアルを実物に合わせられる
- 出力(1シーンから派生):
  - 外観パース 昼・夕(HDRI 差し替え)
  - 内観パース LDK・ガレージ(施策1)
  - 15秒縦型リール+30秒横型ウォークスルー(施策3)
  - 内装バリエーション(壁紙・床材・家具セットの差し替え=ペルソナ別ステージング、施策4)
  - 日照シミュレーション(Sun Position・冬至/夏至・9時/12時/15時、施策5)
- 法規制との相性: 図面に忠実 → 「完成予想図」明記と周辺現況との乖離回避が守りやすい。**建築確認取得済みの物件(浜崎は着工済み)なら広告利用可** ✅
- 差別化: 「AI建築ムービーラボ(1枚9,800円〜・写真から動かすだけ)」に対し、**「図面どおりの家の中を歩ける+日照まで出る+内装差し替え自由」**で戦える

### B. 元ネタどおり: 土地写真 → 提案プラン → ウォークスルー
- 用途: 土地仲介・建築条件付き土地・注文住宅の反響獲得。「この土地に Lancasa ならこう建つ」を SNS/現地看板/商談で見せる
- 制約: 建売としての広告は建築確認前は不可(宅建業法33条 ✅)。建築条件付き土地の「参考プラン」には表示規約上の要件(参考例である旨・建物価格の扱い等)がある ⚠️ → 表示する前に規約の該当条文を確認
- 一級建築士事務所を持つランドスタイルなら **AIの叩き台→女性一級建築士が監修**という見せ方ができ、施策「女性建築士リール」と噛み合う

### C. 中古再販(Relasta)
- 実写があるので3Dの出番は少ないが、**リノベ前物件の「リノベ後イメージ」ウォークスルー**には有効。実測(LiDAR スキャン/間取り図)→3D→仕上げ差し替え

## 5. コスト感 ⚠️

| 項目 | 目安 |
|---|---|
| ソフト | Blender・ffmpeg・Poly Haven: 0円 |
| LLM(Claude Code) | 1物件の初回構築で数十〜百数十万トークン規模。型(テンプレ bpy)ができれば以降は数分の1 |
| レンダー | Mac ローカル: 電気代のみ・数時間/本 / クラウドGPU: 1本 数百円〜千円台 |
| アセット | BlenderKit 有料プラン(必要なら)月 数千円 |
| 人手 | 図面読み・QA・手直し: 初回1〜2日、型ができれば半日/物件 |

既存施策の売価(ビジュアルパック3〜8万円/物件、動画1〜3万円/本)に対し、変動費はほぼゼロに近づく。**投資はすべて「型を作る」初回に集中**する構造。

## 6. リスクと未確認事項

- ❓ 動画本編の品質(X のログイン壁で未視聴)。「サムネイルは写実的」までしか言えない。**自分で PoC を回して品質を確かめるのが最短**
- ❓ 日本の住宅ディテール(引違いサッシ・ユニットバス・システムキッチン)の Blender アセット供給。無ければ最初に自作ライブラリが必要
- ⚠️ LLM の bpy 生成は試行回数がかさむ。Claude Code に画像で結果を返す往復を前提に、トークン費を見込む
- ⚠️ 公正競争規約: 「イメージで実際とは異なります」の注記だけでは免罪符にならない(著しい乖離は不当表示)。図面忠実性を売りにするなら、逆に**差異を出さない運用**を徹底する
- ⚠️ 生成AIの著作権論点は系統2(SD)では残るが、系統5は Blender の通常制作物と同じ扱いになる(Blender は GPL だが出力物には及ばない)
